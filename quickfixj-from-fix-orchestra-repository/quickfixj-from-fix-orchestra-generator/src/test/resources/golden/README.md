# Golden Files for Orchestra Code Generator Regression Tests

This directory contains the reference ("golden") output of `CodeGeneratorJ` (the
orchestra-based code generator) for **FIXLatest**.  They are used by
`OrchestraGoldenFileTest` to catch unintended changes to generated code.

The golden files for the data dictionary generator live in `dictionary/` and are
described in `dictionary/README.md`.

## Directory layout

```
golden/
  fixlatest/   – Java sources generated from OrchestraFIXLatest.xml
  dictionary/  – data dictionary generated from OrchestraFIXLatest.xml (see dictionary/README.md)
```

The test fixture `OrchestraFIXLatest.xml` (in `src/test/resources/`) is a committed copy
of the FIX Latest Orchestra repository (currently `FIX.Latest_EP269`), originally taken from
the `io.fixprotocol.orchestrations:fix-standard` artifact.

All paths below are relative to the repository root.

## What the test does

`OrchestraGoldenFileTest` runs `CodeGeneratorJ` against the fixture into a temporary
folder, with `generateFixt11Package=false` and `excludeSession=true`, then walks every
`.java` file and asserts line-by-line equality with the corresponding file in
`fixlatest/`.  Missing or extra files also fail the test.

## When the generator output changes intentionally

1. Make your generator or XSL changes.
2. If the FIX Latest version changes, replace the fixture
   `quickfixj-from-fix-orchestra-repository/quickfixj-from-fix-orchestra-generator/src/test/resources/OrchestraFIXLatest.xml`
   with the new `OrchestraFIXLatest.xml`.  The data dictionary golden file then needs
   regenerating as well (see `dictionary/README.md`).
3. Regenerate the golden files by running `CodeGeneratorJ` from the command line with the
   same options the test uses, then replace the golden files with the new output.  Delete
   the old directory first so that files the generator no longer produces are removed:
   ```bash
   cd quickfixj-from-fix-orchestra-repository/quickfixj-from-fix-orchestra-generator
   ../../mvnw -q compile dependency:build-classpath -Dmdep.outputFile=target/classpath.txt
   java -cp "target/classes:$(cat target/classpath.txt)" org.quickfixj.orchestra.CodeGeneratorJ \
       -i src/test/resources/OrchestraFIXLatest.xml \
       -o target/golden-fixlatest \
       --generateFixt11Package=false --excludeSession
   rm -rf src/test/resources/golden/fixlatest
   cp -r target/golden-fixlatest src/test/resources/golden/fixlatest
   cd -
   ```
   On Windows use `;` instead of `:` as the classpath separator.  `--excludeSession`
   requires `--generateFixt11Package=false`, because the FIXT11 package is generated by
   default and contains session-layer classes.

   Alternatively, temporarily replace `tempFolder.newFolder("fixlatest")` in
   `OrchestraGoldenFileTest` with `new File("target/golden-fixlatest")`, run the test
   (it fails while the output differs), copy the output as above and revert the change.
4. Verify only the expected files changed:
   ```bash
   git status --short quickfixj-from-fix-orchestra-repository/quickfixj-from-fix-orchestra-generator/src/test/resources/golden/fixlatest
   git diff --stat quickfixj-from-fix-orchestra-repository/quickfixj-from-fix-orchestra-generator/src/test/resources/golden/fixlatest
   ```
5. Run the test suite to confirm the updated golden files now match:
   ```bash
   ./mvnw test -pl quickfixj-from-fix-orchestra-repository/quickfixj-from-fix-orchestra-generator
   ```
6. Commit the updated golden files (and the updated fixture, if applicable) **together
   with your generator/XSL changes** in the same commit (or PR) so reviewers can see the
   diff side-by-side.
